# 使用 CC Switch 连接 Sub2API

这篇教程适合已经拿到 Sub2API API Key，希望在 CC Switch 中切换 Codex、Claude Code 或 Gemini CLI 供应商的用户。

> 本文核对基准为 CC Switch v3.20.1（2026-08-28 发布）。CC Switch 的菜单名称会随版本变化，但配置值和验证方法不依赖截图。

## 开始前准备

你需要以下三项：

- 一个状态正常的 Sub2API API Key；
- 站点提供的 API 地址；
- 你的分组当前允许使用的模型名。

不要把真实 API Key 发到聊天、截图、Issue 或公开仓库。教程中的 `sk-your-key` 只是占位符。

## 先备份现有配置

CC Switch 会把选中的供应商写入对应客户端的实时配置文件。首次启动时，它支持把现有 CLI 配置导入为默认供应商。请先完成导入或使用 CC Switch 的备份功能，再切换供应商。

如果你已经为 Codex 配置了 MCP、权限、通知或其他高级选项，还应单独备份 `~/.codex/config.toml`。供应商切换完成后，对比切换前后的文件，确认无关配置仍然存在。

## 推荐：从站内一键导入

1. 登录 Sub2API。
2. 打开“API 密钥”。
3. 找到要使用的密钥，点击“导入到 CC Switch”。
4. 浏览器询问是否打开 CC Switch 时，确认打开。
5. 在 CC Switch 中检查应用类型、供应商名称、接口地址和模型，再确认导入。
6. 选择刚导入的供应商并点击“启用”。
7. 按 CC Switch 提示重启终端或对应的 CLI 工具。

一键导入会根据密钥所属平台生成配置。不要在没有核对应用类型和模型的情况下直接启用。

## 手动添加供应商

如果浏览器没有拉起 CC Switch，可以在 CC Switch 中点击“添加供应商”，选择对应应用后创建自定义配置。

| 字段 | 示例 | 作用 |
| --- | --- | --- |
| 供应商名称 | `My Sub2API` | 只用于你在 CC Switch 中识别配置 |
| API 地址 | `https://your-sub2api.example` | 使用站点给出的地址，不要猜测域名 |
| API Key | `sk-your-key` | 用于请求鉴权 |
| 模型 | `your-model-id` | 必须是当前密钥所属分组允许的模型 |

不同应用对 API 地址的格式要求不同。Codex 导入使用站点根地址；部分 OpenAI 兼容客户端要求地址以 `/v1` 结尾。如果请求路径出现重复的 `/v1/v1`，删除其中一个 `/v1` 后再试。

## 验证是否生效

先用最小请求验证密钥和地址，再开始长对话。你可以执行“第一次 OpenAI 兼容请求”中的模型列表命令，或在客户端发一条很短的测试消息。

成功时应同时看到：

- 客户端收到正常响应；
- 实际模型与所选模型一致；
- Sub2API 的使用记录中出现本次请求。

## 常见问题

### 返回 `401`

API Key 缺失、复制不完整、已停用或已过期。重新从站内复制密钥，不要在前后保留空格。

### 返回 `404`

通常是 API 地址或路径不对。重点检查是否漏写或重复写了 `/v1`。

### 提示模型不存在

模型名不在当前分组的允许范围内。回到站内查看可用渠道或模型广场，再使用显示的完整模型 ID。

### 切换后 Codex 的其他设置丢失

先停止继续切换，恢复之前备份的 `~/.codex/config.toml`。再对比新旧文件，只保留本次供应商所需的路由字段，不要整份覆盖。
