# 使用 CC Switch 接入 Codex

这篇教程从创建 Sub2API API Key 开始，带你把 Codex 接入 CC Switch，并完成一次最小请求验证。完成后，CC Switch 会把选中的 Sub2API 供应商写入 Codex 的配置，后续可在 CC Switch 中切换供应商。

> 本文只介绍 API Key 方式，不涉及 OpenAI 官方 OAuth 登录。请把 Sub2API API Key 当作密码保管，不要提交到 Git、聊天记录、截图或公开 Issue。

## 你需要准备什么

- 一个可以登录的 Sub2API 账号；
- 一个可用的分组。分组决定这把密钥可以访问哪些模型和路由；
- 已安装 CC Switch，并且系统允许浏览器打开 `ccswitch://` 链接。可以从 [CC Switch 官方网站](https://www.ccswitch.io/zh/) 获取安装包和文档；
- 已安装 Codex CLI 或 Codex Desktop。如果需要桌面安装包，可以参考 [Codex 镜像下载项目](https://github.com/Wangnov/codex-app-mirror)；这是第三方镜像项目，不是 OpenAI 官方分发渠道，下载后请自行核对 Release 和校验信息。

如果你还没有确认分组和模型，先不要创建密钥。创建后发现分组不正确，可以在 API 密钥列表中修改分组；修改会影响这把密钥后续能访问的模型。

## 第一步：创建 Sub2API API Key

1. 登录 Sub2API，进入左侧的“API 密钥”页面。
2. 点击“创建密钥”。
3. 在“名称”中填写便于识别的名称，例如 `Codex - MacBook`。
4. 在“分组”中选择要给 Codex 使用的分组。这个字段是必选项。
5. 第一次接入时，建议先保持以下可选项关闭或留空：
   - 自定义 Key：不需要自己指定字符串，让系统生成即可；
   - IP 限制：确认网络环境稳定后再配置；
   - 额度、5 小时/1 天/7 天限流：不需要限制时保持为 `0` 或关闭；
   - 过期时间：不需要临时密钥时保持关闭。
6. 点击“创建”。
7. 创建成功后，回到密钥列表，确认这把密钥的状态为“启用”，并确认它已经绑定到正确分组。

如果创建失败，优先检查是否选择了分组。Sub2API 不允许创建没有分组的用户 API Key。

## 第二步：从 Sub2API 导入到 CC Switch

1. 回到 Sub2API 的“API 密钥”列表，找到刚创建的密钥。
2. 点击该行操作区的“导入到 CCS”。这个按钮只在管理员没有关闭 CCS 导入功能时显示。
3. 浏览器询问是否打开 CC Switch 时，允许打开。
4. CC Switch 打开后，检查导入预览中的以下内容：
   - 应用类型是 `Codex`；
   - 供应商名称是当前站点名称；
   - API 地址是 Sub2API 提供的站点根地址；
   - API Key 是刚创建的密钥；
   - 模型默认是 `gpt-5.5`。
5. 确认导入，回到 CC Switch 的供应商列表。
6. 选中刚导入的供应商，点击“启用”或对应的切换按钮。

当前 Sub2API 的 OpenAI/CC Switch 导入链路会把应用类型设为 `codex`，并使用站点根地址作为 endpoint。不要自行在这个地址后面追加 `/v1`，否则某些客户端可能请求成 `/v1/v1/...`。

### 如果没有“导入到 CCS”按钮

可能原因有三种：

- 当前站点管理员关闭了 CCS 导入按钮；
- 这把密钥没有绑定分组；
- 浏览器或系统没有注册 `ccswitch://` 协议。

这时可以在 CC Switch 中手动添加供应商，字段按下面填写：

| 字段 | 填写方式 |
| --- | --- |
| 应用类型 | `Codex` |
| 供应商名称 | 任意便于识别的名称，例如 `Sub2API` |
| API 地址 | Sub2API 提供的站点根地址，例如 `https://your-sub2api.example` |
| API Key | 刚创建的用户 API Key |
| 模型 | 分组允许的模型；可以先填 `gpt-5.5`，若不可用则改为分组中实际存在的模型 |

手动添加时，不要把 API Key 写进公开配置文件或提交到仓库。

## 建议开启 Codex 应用增强

完成供应商导入后，打开 CC Switch 设置中的“Codex 应用增强”，建议直接开启以下两项：

1. **非接管切换时保留官方登录**：未开启路由接管时，切换第三方供应商仍保留 Codex 官方登录；在路由接管期间也会始终保留官方登录。
2. **统一 Codex 会话历史**：让官方订阅与第三方供应商的会话出现在同一历史列表中，并支持把现有官方会话迁入。迁移前 CC Switch 会自动创建备份；关闭该选项后，也可以按备份恢复已迁入的会话。

“统一 Codex 会话历史”有一个需要提前知道的限制：跨供应商继续旧会话时，对方后端可能无法解密会话中的 `encrypted_content` 推理内容，导致继续会话失败。遇到这种情况，改为新建会话，或切回原来的供应商继续。

## 第三步：重启 Codex 并验证

1. 完全退出 Codex CLI 或 Codex Desktop。只关闭当前任务或终端标签页可能不会重新读取配置。
2. 重新打开 Codex。
3. 新建一个很短的任务，例如让 Codex 返回一句确认文本。
4. 确认请求能够得到正常响应。
5. 回到 Sub2API，检查使用记录中是否出现这次请求。

如果你想先验证密钥和地址，再排查 CC Switch，可以执行 Wiki 中的[第一次 OpenAI 兼容请求](/wiki/getting-started/first-openai-request)。这个请求只读取模型列表，不会生成长文本。

## 你应该看到的结果

接入成功通常同时满足：

- CC Switch 中的供应商状态为启用；
- Codex 可以创建新任务并收到响应；
- 使用的模型属于这把密钥绑定分组允许的范围；
- Sub2API 的使用记录出现对应请求。

只看到 CC Switch 显示“启用”还不够。最终以 Codex 的真实响应和 Sub2API 使用记录为准。

## 常见问题

### CC Switch 没有被打开

确认系统中已经安装 CC Switch，并允许浏览器打开 `ccswitch://`。如果仍然失败，使用上面的手动添加方式。

### Codex 返回 `401`

通常是 API Key 缺失、复制不完整、已停用或已过期。回到 Sub2API 的 API 密钥页面确认状态为“启用”，然后重新导入。不要在 Key 前后加入空格。

### Codex 返回 `404`

重点检查 API 地址。OpenAI/CC Switch 导入使用站点根地址；不要重复追加 `/v1`。如果你手动填写的地址已经包含 `/v1`，请按 CC Switch 当前应用的字段说明确认是否需要移除。

### 提示模型不存在

当前模型不在密钥绑定分组的允许范围内。回到 Sub2API 查看该分组可用的模型，或者在 CC Switch 中把模型改成实际可用的完整模型 ID。当前自动导入默认使用 `gpt-5.5`，它不一定在每个分组中可用。

### 重启后仍然使用旧供应商

确认 CC Switch 中新供应商仍处于启用状态，并且你完全退出后重新启动了 Codex。然后检查 `~/.codex/config.toml` 的 `[model_providers.OpenAI]` 配置是否已更新。

### 切换后其他 Codex 设置丢失

先退出 Codex，不要继续重复切换。重新打开 CC Switch，确认当前启用的供应商、API 地址和模型，再启动 Codex。必要时检查 `~/.codex/config.toml` 中的 `[model_providers.OpenAI]` 配置；不要直接把不明来源的完整配置覆盖到现有文件。

## 安全提醒

- API Key 等同于密码；任何拿到它的人都可能消耗你的额度；
- 不要把真实 Key 粘贴到聊天、截图、Issue、仓库或录屏中；
- 不使用的 Key 应及时停用或删除；
- 如果怀疑泄露，立即停用旧 Key 并创建新 Key；
- 不要为了排查问题，把带真实 Key 的 `config.toml` 或 `auth.json` 发给他人。
