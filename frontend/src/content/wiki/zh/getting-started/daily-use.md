# 本站用户日常使用指南

这篇指南面向已经注册并能登录本站的普通用户。你可以用它完成日常最常见的操作：充值、查看余额和用量、核对使用记录、判断渠道是否可用，以及在请求失败时整理信息联系管理员。

> 本站目前采用人工充值：需要先联系管理员，由管理员确认后为账户增加余额。不要向任何人提供登录密码、API Key、Cookie、验证码或完整配置文件。

## 每次使用前先看什么

登录后先进入左侧的“仪表盘”，快速检查以下信息：

- **余额**：当前可用于按量计费请求的可用余额；
- **API 密钥**：密钥总数和处于启用状态的数量；
- **今日请求、今日消费**：判断当天是否已经产生调用和扣费；
- **今日 Token、累计 Token**：了解文本请求的输入、输出和缓存用量；
- **最近使用**：快速核对最近请求的模型、时间、Token 和费用；
- **平台配额**：如果管理员为你的账户配置了平台限额，这里会显示日、周或月用量。

页面右上角也会显示可用余额。鼠标移到余额上时，部分页面还会显示可用余额、冻结金额和总余额。

### 可用余额和冻结金额的区别

- **可用余额**：现在可以继续消费的金额；
- **冻结金额**：已经被任务预占、但尚未完成最终结算的金额；
- **总余额**：可用余额与冻结金额之和。

批量任务等场景可能先冻结预计费用，完成后再结算或释放剩余金额。发现冻结金额长时间没有变化时，先刷新页面；如果对应任务已经结束仍未恢复，再把任务时间和请求 ID 发给管理员核查。

## 如何充值

本站目前没有开放用户自助充值，充值需要联系管理员。

1. 登录本站，确认正在使用正确的账号。
2. 记下你的注册邮箱或用户名，以及希望充值的金额。
3. 通过本站公布的联系方式联系管理员。若站点已配置客服信息，可在左侧“个人资料”页面查看。
4. 按管理员提供的方式完成确认。转账前核对收款对象和金额，不要仅凭陌生私信操作。
5. 管理员通知充值完成后，刷新页面并检查右上角余额或“仪表盘”中的余额。
6. 如果余额没有更新，退出后重新登录一次；仍未到账时，把账号、金额、付款时间和已脱敏的付款凭证发给管理员。

向管理员反馈充值问题时，**不需要**发送 API Key、密码、Cookie 或验证码。付款凭证应遮住与问题无关的银行卡号、身份证号、家庭住址等隐私信息。

### 如果你拿到了兑换码

左侧出现“兑换”入口时，可以进入页面输入兑换码。兑换码区分大小写，可能增加余额、并发数或订阅。兑换成功后，页面会显示新的余额或权益，并在最近活动中留下记录。

兑换码不是默认充值方式。没有兑换码时，仍按上面的人工充值流程联系管理员。

## 查看用量概览

“仪表盘”适合快速看概况，“使用记录”适合核对每一次请求。

在仪表盘中可以调整时间范围和统计粒度，查看：

- 模型、分组和平台的用量分布；
- Token 使用趋势；
- 请求数、实际消费和标准费用；
- RPM、TPM、平均响应时间等性能指标；
- 最近几条使用记录。

费用同时出现“实际”和“标准”时：

- **实际**表示本站对该请求记录的实际扣费；
- **标准**表示请求在标准价格下的参考费用。

日常核对余额变化时以“实际”为准。倍率、分组或历史价格发生变化时，实际费用可能与标准费用不同。

## 查看每一次使用记录

进入左侧“使用记录”，先选择时间范围，再按需要筛选。页面支持按以下条件组合查询：

- API 密钥；
- 模型；
- 分组；
- 请求类型，例如流式、同步或 WebSocket；
- 计费类型，例如余额或订阅；
- 计费模式，例如按 Token、按次、按图片或按视频。

上方统计卡和图表可用于看整体趋势；下方表格用于核对单次请求。常用字段包括：

- 请求时间和请求 ID；
- 使用的 API 密钥、分组和模型；
- 输入、输出、缓存 Token；
- 实际费用；
- 首 Token 延迟和总耗时；
- 请求类型、端点和客户端 IP。

表格右上角的“列设置”可以隐藏暂时不关心的字段。“导出 CSV”可以导出当前筛选范围内的记录，适合自己对账；导出的文件也可能包含请求时间、IP、模型和密钥名称，不要直接公开分享。

### 请求成功了，但暂时看不到记录

1. 确认筛选的时间范围包含请求发生时间。
2. 点击“刷新”，并清除模型、密钥或分组筛选后再看。
3. 确认客户端实际使用的是本站 API Key，而不是其他供应商或官方登录。
4. 再发起一次很短的真实模型请求，然后记录发生时间。
5. 仍没有记录时，把时间、模型、客户端名称和已脱敏的请求地址发给管理员。

## 查看错误请求

如果管理员开启了用户错误记录，“使用记录”页面会出现“错误请求”标签。你可以按 API 密钥、模型、错误分类和状态码筛选，并查看错误时间、端点、平台和错误信息。

常见分类包括认证失败、限流、余额或订阅不足、参数错误、上游错误和平台错误。排查时先记录：

- 发生时间和时区；
- HTTP 状态码；
- 请求 ID；
- 模型名和客户端名称；
- 已脱敏的错误信息。

然后参考 Wiki 的[请求失败时先看这里](/wiki/troubleshooting/request-errors)。错误详情可能包含上游返回内容，分享截图前同样需要检查并遮住敏感信息。

## 查看自己能用哪些渠道和模型

如果左侧有“可用渠道”，进入后可以查看当前账号可访问的：

- 渠道名称和平台；
- 公开分组或管理员授权的专属分组；
- 支持的模型；
- 按 Token、按次、按图片或按视频的定价信息。

页面顶部可以按渠道名、平台、分组或模型搜索。创建或修改 API Key 前，先在这里确认目标模型属于你可以访问的分组。

“可用渠道”只说明你**有权使用什么**，不代表该渠道此刻一定处于最佳状态。

## 查看渠道当前状态

如果左侧有“渠道状态”，进入后可以查看渠道的可用性、延迟和近期趋势。站点可能使用不同版本的状态页，因此你看到的指标会略有不同，常见内容包括：

- 正常、降级、失败等健康状态；
- 近期可用率和错误率；
- 首 Token 延迟、总延迟或吞吐；
- 不同平台、分组和模型的趋势；
- 最近更新时间和数据覆盖范围。

选择模型时建议按下面的顺序判断：

1. 先到“可用渠道”确认账号有权访问目标分组和模型。
2. 再到“渠道状态”查看对应平台或模型近期是否正常。
3. 如果状态显示降级或失败，先换用同分组内其他可用模型，或稍后重试。
4. 如果状态页正常但你的请求持续失败，再到“使用记录”或“错误请求”查单次请求。

渠道状态是基于监控或近期请求形成的参考信息，不保证每一次请求都成功。页面没有某个渠道，也可能只是管理员没有把它加入公开监控。

## 日常维护 API Key

进入左侧“API 密钥”，建议定期检查：

- 正在使用的密钥状态是否为“启用”；
- 密钥是否绑定了正确分组；
- 最近使用时间和最近使用 IP 是否符合预期；
- 是否设置了总额度、时间窗口限额、IP 限制或过期时间；
- 已经不用的密钥是否可以停用或删除。

如果发现陌生 IP、异常用量或怀疑密钥泄露，应立即停用旧密钥、创建新密钥，并更新客户端配置。不要在聊天记录、截图、Issue 或仓库中粘贴完整 API Key。

## 订阅、订单和其他入口

不同账号和站点配置看到的菜单可能不同：

- **我的订阅**：查看当前订阅、有效期、用量和重置时间；
- **充值/订阅、我的订单**：只有管理员启用在线支付后才会出现；本站当前充值仍以联系管理员为准；
- **个人资料**：查看账户信息、客服联系方式，以及管理员启用的余额不足提醒和安全设置；
- **公告**：留意维护、模型调整、价格变化或临时故障通知。

某个入口没有显示，通常表示管理员未启用该功能、当前账号没有权限，或站点处于简易模式，并不一定是页面故障。

## 联系管理员时怎么描述问题

为了减少来回确认，建议一次提供：

1. 注册邮箱或用户名；
2. 问题发生时间和时区；
3. 使用的客户端、模型和 API Key 名称；
4. 请求 ID、HTTP 状态码和已脱敏的错误信息；
5. 你已经检查过的页面，例如余额、使用记录、可用渠道和渠道状态；
6. 与问题直接相关的脱敏截图。

不要提供登录密码、完整 API Key、Cookie、OAuth Token、验证码或未经检查的完整配置文件。管理员通常只需要 API Key 的名称，不需要密钥正文。

## 建议的日常检查顺序

遇到问题时按这个顺序通常最快：

1. 看右上角或仪表盘中的可用余额；
2. 看 API Key 是否启用并绑定正确分组；
3. 看“可用渠道”中是否有目标模型；
4. 看“渠道状态”是否正常；
5. 看“使用记录”或“错误请求”的状态码和请求 ID；
6. 带着脱敏信息联系管理员。
