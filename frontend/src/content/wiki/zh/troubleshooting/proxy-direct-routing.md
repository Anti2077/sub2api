# 网站无法访问：让 anti2077.xyz 走直连

如果本站在浏览器中打不开、登录页一直加载，或 API 客户端连接超时，先检查代理规则。某些代理订阅会把所有流量交给代理节点；当节点、地区路由或 DNS 解析不适合本站时，访问就可能失败。

本文会把 `anti2077.xyz` 及其全部子域名指定为直连（`DIRECT`）。这只影响本站域名，不会关闭你的代理，也不会改变其他网站的代理规则。

> 只添加域名规则，不要把 API Key、Cookie、订阅链接或完整配置文件发送给他人。本文使用的是公开的站点域名，不需要填写账号或密钥。

## 你需要准备什么

- 正在使用的代理客户端，例如 Clash Verge Rev、Shadowrocket、Surge、Stash 或 sing-box；
- 能编辑当前启用配置、覆写（Override）或规则的权限；
- 已确认当前使用的是哪个配置或订阅。

订阅更新后，直接修改订阅文件的规则通常会被覆盖。优先使用客户端提供的“覆写”“扩展配置”“模块”或“本地规则”功能；如果客户端没有这些功能，再在每次更新订阅后重新加入规则。

## 要添加的规则

多数 Clash/Mihomo 兼容客户端使用下面这一行：

```text
DOMAIN-SUFFIX,anti2077.xyz,DIRECT
```

它的含义是：

- `DOMAIN-SUFFIX`：按域名后缀匹配；
- `anti2077.xyz`：匹配根域名和所有子域名，例如 `www.anti2077.xyz`；
- `DIRECT`：不通过代理节点，直接连接。

如果客户端把策略显示为“直连”而不是 `DIRECT`，选择“直连”即可。规则必须放在订阅规则中的广泛匹配项、`MATCH`、`FINAL` 或“所有流量走代理”规则之前；规则通常从上到下依次匹配，先命中的规则会生效。

## Clash Verge Rev

1. 打开 Clash Verge Rev，确认当前正在使用的配置或订阅。
2. 进入该配置的“覆写”“脚本”或“规则编辑”入口。不同版本的入口名称可能不同，目标是为当前配置追加本地规则，而不是直接改远程订阅原文。
3. 在规则列表中添加：

   ```text
   DOMAIN-SUFFIX,anti2077.xyz,DIRECT
   ```

4. 把这条规则移动到 `MATCH`、`FINAL`、`GEOIP` 或其他通配规则之前。
5. 保存并重新载入当前配置。若客户端显示规则命中日志，访问本站时应看到策略为 `DIRECT` 或“直连”。

如果使用 YAML 覆写，规则段通常形如：

```yaml
rules:
  - DOMAIN-SUFFIX,anti2077.xyz,DIRECT
```

保留已有的 `rules:` 内容；不要只粘贴这一小段覆盖完整配置。把新规则放在现有兜底规则之前。

## Shadowrocket（iPhone/iPad）

1. 打开 Shadowrocket，进入“配置”，找到当前已启用的配置。
2. 打开配置的规则编辑页面，添加一条规则。
3. 规则类型选择 `DOMAIN-SUFFIX`。
4. 域名填写 `anti2077.xyz`。
5. 策略选择 `DIRECT` 或“直连”，然后保存。
6. 确认新规则位于 `FINAL` 或其他广泛规则之前，再重新连接代理。

Shadowrocket 的订阅配置可能在更新后恢复原状。若规则会消失，使用“本地规则”或模块功能保存这条规则，而不是只改远程订阅。

## Surge（macOS/iPhone/iPad）

在当前配置的 `[Rule]` 段中，放在 `FINAL` 前面添加：

```ini
DOMAIN-SUFFIX,anti2077.xyz,DIRECT
```

保存后重新载入配置。若当前配置来自订阅，使用 Surge 的模块或覆写机制保存规则，以免下次更新订阅时被覆盖。

## Stash

Stash 使用 Clash/Mihomo 风格规则。通过当前配置的覆写或本地规则功能添加：

```text
DOMAIN-SUFFIX,anti2077.xyz,DIRECT
```

保存后重新载入配置，并把它排在 `MATCH`、`FINAL` 或其他兜底规则之前。不要把 `DIRECT` 改成某个代理策略组名称，否则该域名仍会经过代理。

## sing-box

编辑 sing-box JSON 配置时，在 `route.rules` 数组的兜底规则之前添加一条路由规则：

```json
{
  "domain_suffix": ["anti2077.xyz"],
  "action": "direct"
}
```

保存后先执行客户端的配置检查或重载，再重新连接。不要把它加在已有的最终匹配规则之后；那样最终规则已经先匹配，直连规则不会执行。

## 验证是否生效

1. 保持代理客户端已连接，打开 `https://anti2077.xyz`。
2. 确认网站可以加载、登录页不再无限转圈，并尝试执行一个不消耗额度的操作，例如打开首页或登录页。
3. 打开代理客户端的连接或规则日志，确认访问 `anti2077.xyz` 时命中 `DIRECT`、`直连` 或本地直连规则。
4. 如果你同时使用 API 客户端，再重新执行一次最小请求。可参考 Wiki 中的[第一次 OpenAI 兼容请求](/wiki/getting-started/first-openai-request)。

只看到网站偶尔能打开并不能证明规则正确；应以规则日志命中直连和稳定访问为准。

## 仍然无法访问时

### 规则没有命中

确认规则放在 `MATCH`、`FINAL`、`GEOIP` 或代理组通配规则之前。还要确认编辑的是当前启用的配置，而不是另一个未启用的订阅。

### 更新订阅后规则消失

不要继续直接编辑订阅原文。改用本地规则、覆写、扩展配置或模块功能，再重新更新订阅确认规则仍在。

### 日志显示已直连但仍超时

暂时关闭该域名的直连规则进行一次对比：如果恢复代理后可以访问，保留代理路线并联系站点支持；如果两种路线都不通，记录发生时间、客户端名称、客户端版本和已脱敏的错误信息后再提交问题。不要附上 API Key、Cookie 或完整订阅链接。

### 只有 API 客户端失败

浏览器能打开不代表 API 客户端的地址正确。继续检查客户端中的 Base URL、是否重复添加 `/v1`、API Key 状态和模型名称；可先完成[第一次 OpenAI 兼容请求](/wiki/getting-started/first-openai-request)来区分网络问题与客户端配置问题。
