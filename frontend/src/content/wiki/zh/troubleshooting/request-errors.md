# 请求失败时先看这里

先记录 HTTP 状态码和错误正文，再修改配置。只看“请求失败”四个字通常无法判断问题在哪一层。

## 快速判断

| 现象 | 常见原因 | 先检查什么 |
| --- | --- | --- |
| `401 Unauthorized` | API Key 缺失、无效、停用或过期 | 鉴权头和密钥状态 |
| `403 Forbidden` | 当前用户或分组没有访问权限 | 分组、订阅与功能权限 |
| `404 Not Found` | 地址或端点路径错误 | 域名、`/v1` 和具体端点 |
| `429 Too Many Requests` | 额度、并发或速率限制 | 余额、密钥限制和稍后重试 |
| `5xx` | 上游或网关暂时异常 | 使用记录、渠道状态和请求 ID |
| 连接超时 | 网络、代理、DNS 或 TLS 问题 | 用 `curl` 对同一地址做最小请求 |

## 最小化复现

1. 暂时绕过 GUI 客户端，使用“第一次 OpenAI 兼容请求”中的模型列表命令。
2. 保留状态码、错误正文和请求 ID，但删除 API Key。
3. 如果模型列表成功，再回到客户端检查 Base URL、模型和代理设置。
4. 如果模型列表也失败，先处理密钥、地址或站点侧状态。

## 提交问题时可以提供

- 发生时间和时区；
- 客户端名称与版本；
- 已脱敏的请求地址和模型名；
- HTTP 状态码、错误正文和请求 ID；
- 是否能成功请求 `/v1/models`。

不要提供完整 API Key、Cookie、OAuth Token、私有配置文件或未经脱敏的截图。
